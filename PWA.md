# Installation and app icons

The public web app manifest supplies a stable app ID, relative start URL and scope,
standalone display, and the game's paper and sea colors. Relative URLs preserve
Vite's support for hosting under a subdirectory. No orientation lock is requested;
the existing responsive game handles tablet and phone rotation.

Chrome installation requires HTTPS in production (localhost works for development).
Use the install icon in desktop Chrome, or **Add to home screen → Install** in
Android Chrome when offered. A plain home-screen shortcut and an installed Android
WebAPK are different: a WebAPK also appears in Android's installed-app list.

This change provides installation and icons, not offline support. It does not add
a service worker or cache game assets. Chrome supports installation from its menu
without a service worker, and saves continue to use the game's existing browser
storage.

## Icon files

Run `pnpm icons` to regenerate the original green/pink crayon mark from
`scripts/app-icons.js`. The script uses the existing Sharp development dependency.
Generated files live alongside the source, so ordinary builds need no
extra generation step. Vite copies `public/` unchanged into `dist/`.

| File                                                | Use                                              |
| --------------------------------------------------- | ------------------------------------------------ |
| `public/favicon.svg`                                | Scalable browser tab icon                        |
| `public/favicon.ico`                                | 16, 32, and 48px browser fallback                |
| `public/apple-touch-icon.png`                       | 180px Apple home-screen icon                     |
| `public/icons/icon-192.png`, `icon-512.png`         | Larger-mark artwork exports                      |
| `public/icons/maskable-192.png`, `maskable-512.png` | Shared manifest sources for `any` and `maskable` |

Maskable icons have an opaque, full-bleed paper background. Their crayon mark is
inside the centered circle with a radius of 40% of the image width, keeping it
visible under circular and other launcher masks. The regular version has a larger
mark for surfaces that do not crop icons. Neither version contains source photos,
personal metadata, or external image references.

At each size, the manifest declares the same mask-safe image twice. The entries
are identical except for `purpose: any` and `purpose: maskable`, as requested.

## Google Kids Space

Google does not document a separate Kids Space favicon or web-manifest icon member
in its public help. The standard web declaration is the manifest's `icons` array.
Chrome uses that metadata when generating the installed Android WebAPK; its native
manifest declares the application icon as `android:icon="@mipmap/ic_launcher"`.
That native resource is generated by Chrome, not controlled by an HTML meta tag.

The reported Berenstain case is specifically a generic triangle/circle/square icon
in Kids Space, while Pixel Launcher on the same tablet displays the correct icon.
The local Berenstain project already contained valid 192px and 512px PNGs, with the
512px entry declared only as `maskable`. At the user's request, that entry was
duplicated with `purpose: any`, keeping the same image URL and other fields.
Providing both purposes at both sizes is a compatibility improvement, implemented
here, but is **not a verified fix** for that other app or for Kids Space.

Because the normal launcher can display the installed icon, the symptom suggests
a Kids Space icon-loading/cache issue or WebAPK compatibility problem, rather than
simply an absent large image. This remains a hypothesis: the screenshot cannot
reveal the installed APK's resources, and the local files do not prove what the
deployed Berenstain site currently serves. A 1024px image is not a documented Kids
Space requirement. The Berenstain change has not been verified on the tablet.

To check on the tablet after deploying this app:

1. Open the HTTPS site in Chrome and install it in the child's Android profile.
2. Confirm it appears in Android Settings' app list, then compare Pixel Launcher
   and Kids Space. Check that Family Link allows the app if necessary.
3. If only Kids Space shows the placeholder, update Chrome/Kids Space and restart
   the tablet. Report the differing launcher behavior through Kids Space's
   **Parent Menu → Help & feedback** if it persists.

For an existing installation, changing web icon files does not immediately replace
the installed APK's icon. Chrome has a separate WebAPK update process. Avoid
clearing game/browser storage when checking icons, since it contains saved progress.

## Validation

Run `pnpm icons`, `pnpm build`, and `pnpm start`. In Chrome DevTools, inspect
**Application → Manifest**: no installability errors, all four PNGs load, and the
maskable safe-area overlay contains both crayons. The manifest and every icon
should return HTTP 200 with the correct content type from the production server.
Device testing is still required to verify Google Kids Space rendering.
